Review The Code

  1. Line 21: What does this function do? If you change “resolve” to “fulfil” in the parameter, what else do you need to change in the function?

This functions simulates an async task where it calls either resolve(value) if the process is successful, or it calls reject(error) if it fails. If we were to rename resolve to fulfil, then we would have to change resolve(“Hello World!”); to fulfil(“Hello World!”);. Otherwise it breaks because resolve no longer exists.

  1. Line 47: Note: There are two parameters in the async_simulate function. But no arguments are supplied in this statement. Where will the arguments be supplied?

The Promise constructor automatically passes resolve and reject. So even though we don’t see the arguments, they are provided internally by JavaScript.

  1. Line 47, 53: Can you combine these two lines into one statement?

Yes, lines 47 and 53 can be combined.

Original:
let promise = new Promise(async_simulation);
promise.then(dataLoaded, loadFailed);

Combined version:
new Promise(async_simulation).then(dataLoaded, loadFailed);

Revise The Code

  1. The current async function returns a string value “Hello World!”. Revise the code so the returned value is an object: {last: “Smith”, first: “John”, age: 21}. Display the Full Name and Age when the function is successful.

  1. Follow the instructions on Line 59-62 and run code again. What do you observe?

The program blocks immediately, there is no async behavior, and everything now runs in order. Essentially, Promise = non-blocking, resolve() → success, reject() → failure, .then(success, failure) handles both, and without Promise → everything becomes blocking.
